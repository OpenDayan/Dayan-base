# dyperf JSON task report

An independent Python 3.8+ tool. It reads existing dyperf Chrome Trace JSON;
no changes to dyperf, device kernels, runtime or firmware are required.
It does not launch a workload unless the optional shell wrapper is used.

## Existing trace

```bash
python3 host/dyperf-report/dyperf_report.py trace.json
```

Each completed user task prints TASK_PERF, with its source file, name, core,
tid, start/end counters and elapsed cycles. Performance Summary reports count,
arithmetic mean, minimum and maximum by task name and core.

## Three repeats of the same workload

```bash
python3 host/dyperf-report/dyperf_report.py repeat1.json repeat2.json repeat3.json \
  --task softmax --csv summary.csv
```

Inputs are combined by name and core. Pass only the same shape/configuration
per invocation for per-workload comparisons; shape is not recorded in task names.
Use --by-file to retain separate per-file Summary rows. Duplicate paths are
rejected to prevent accidental double counting. --task filters exact names.

## Capture and print in one command

```bash
set -o pipefail
bash host/dyperf-report/run_with_report.sh /tmp/softmax.json \
  --pcu-interval 0 -- /path/to/test-backend-ops test ... \
  2>&1 | tee /tmp/softmax.log
```

The wrapper invokes the original dyperf, waits for a successful capture, then
automatically prints the report. Set DYPERF to override the executable path.
No report is generated by the wrapper if capture/workload execution fails.
For failed captures, analyze the JSON separately only if it is a complete JSON
document; proc-state data alone cannot certify workload correctness or profiler
buffer integrity. Preserve the original correctness log alongside the trace.

## Measurement definition and limits

- Elapsed cycles: first RUNNING begin through WAIT_EXIT begin, including waits.
  These are not summed RUNNING segments or host wall-clock time.
- Only proc_state args.counter is used. PCU cycle samples and ts are not timing
  inputs. The existing 48-bit counter wrap is extended per process/core in file
  order, using both B and E records. Reordered traces are rejected. Multiple
  unobserved counter wraps cannot be recovered from raw counters alone.
- Scheduler, rpc-receive, rpc-send, profile-flush and PCU tracks are excluded.
- Unfinished tasks, missing starts, never-started tasks and unnamed tracks are
  listed under Excluded. --strict returns 1 for excluded or empty results.
- Malformed input or I/O errors return 2; normal reports return 0.
- Start capture before the workload; already-running task starts cannot be
  reconstructed. Parent/child intervals can overlap, so do not sum their rows
  as device elapsed time.
- Missing core metadata keeps PIDs separate across files rather than merging
  unrelated cores. Metadata names are read before processing state records.
- Mean uses integer sums and decimal formatting, rounded to 3 decimal places.
- This tool does not change prior reports from median to arithmetic mean.
